# 数学分析16窗口与高代的协作约定

一个窗口负责一个有边界的主题，使用同一[提示词](chatgpt-learning-prompt.md)。已有16窗口和教材分工优先；下表是**尚未有既定分工时的建议**，不是对现有教材、强化讲义或裴礼文目录的转录。窗口号不是章节号，不据此填number。已有章节ID优先，下面ID只供新项目选择。

| 窗口 | 建议范围 | 新章节ID示例 |
| --- | --- | --- |
| 01 | 实数完备性、数列极限 | ma-sequences |
| 02 | 函数极限、连续、一致连续 | ma-continuity |
| 03 | 导数、微分、中值定理 | ma-derivatives |
| 04 | Taylor公式、极值、不等式应用 | ma-taylor |
| 05 | 不定积分与原函数 | ma-antiderivatives |
| 06 | 定积分、可积性、微积分基本定理 | ma-integrals |
| 07 | 反常积分 | ma-improper |
| 08 | 数项级数 | ma-series |
| 09 | 函数列、函数项级数、一致收敛 | ma-uniform |
| 10 | 幂级数与Fourier级数 | ma-expansions |
| 11 | 多元极限、连续、可微 | ma-multivariable |
| 12 | 高阶微分、隐函数、条件极值 | ma-implicit |

同一窗口可负责多个已存在章节，不强行一窗一章。高代同样按主题分配，如alg-polynomials、alg-determinants、alg-linear-maps；不要把已有ch02更名为alg-determinants。例子文件使用新主题ID以免冒充实际教材编号。

## 共享清单

在总窗口维护一份从真实JSON提取的清单：章节ID、subjectId、标题，以及节点ID、chapterId、title。只共享各窗口需要的条目；实际讲解与个人反馈留在对应资料中。每次开新窗口提供相关旧JSON或清单，使“同一内容沿用同一ID”有可靠依据。

首次没有历史资料时即可按主题创建，不需要为了建立目录提前编造5000个空节点。分组建议“基础与推导”“数学思想与题型”“疑难与检验”；这只是教学结构，不是必须发明的新字段。

## 两种交付情形

**本次独立主题**：窗口交付有完整章节和父分组的有效JSON。跨窗未来关系写在正文“待建立联系”；当前related只用本文件节点。可以直接检查和导入。

**本次要连跨窗口知识网**：把相关窗口当前版本一起交给汇总窗口，提供真实目标ID，将相关节点加入related，运行多文件合并命令。相关文件分别检查可能出现“reference不在本包”，这是待合并状态；最终合并包必须完全通过。不要把依赖文件散放ZIP就称为关联已经修复。

例如数列递推母题与数项级数的误差估计，两个节点共同放入合并包并互相related。高代的秩一结构与数分的局部线性化只有在正文说明共同结构和边界时才连接，不把“都叫线性”当作充分依据。

## 更新与反馈

- 每个ID在本轮汇总中只保留一个完整版本。两个窗口都修改了同一节点时，工具报告merge-conflict；人工/AI依据实际记录合并内容后再检查，不能悄悄取最后一个。
- 保留稳定chapterId；更换章意味着插件会视为另一身份，旧条目不会自动删除。
- 当你提交作答，把原题ID、真实解答、看过的提示和卡点一起给负责窗口。生成question节点或更新已有question节点，保留真实证据；不从一般易错点推断你的缺陷。
- 同一个自测第一次没做，记录“未检验”；之后有真实作答才补充诊断。复习台个人标记与Obsidian“我的笔记”不由ChatGPT伪造，也不从资料导入自动获得。
- 更新带跨章related的节点时，仍需把目标节点放在当前合并JSON里，不能只导入一条孤立更新而期待跨章链接自动保留。
- 在库内个人笔记区写理解；来源讲解更新会由已有插件合并策略处理。Obsidian与复习台是单向交接，不自动双向同步。
